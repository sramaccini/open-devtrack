| [23](adr-23-hardening.md) | Hardening for 1.0: ASVS level 2 and WCAG 2.2 AA | A requirement list, OSV-Scanner, CodeQL and a ZAP baseline in CI; webhook secrets encrypted; row-level security if the load test allows; axe-core on the main screens and a manual check per release | Accepted |
| [24](adr-24-security-open-items.md) | The open security items that need a decision (ASVS level 2) | Signed images with the release, a Keycloak theme with a strength meter, pepper and OTP notice accepted, a recent login (A8), a key plugin for Vault transit, rate limit (A9) and Prometheus alerts, export and pseudonymised removal of a user, attachment quota, type by content and clamd hook, requests checked against the OpenAPI | Accepted |

| [26](adr-26-backlog-as-search-table.md) | The backlog as a search table (supersedes the backlog of ADR-15) | The backlog screen is an ODQL query and a `serverDataTable` grouped by sprint; the sprint in the rows, columns and groups of the search; row actions «Move to sprint…», «To the top», «To the bottom»; the order by drag stays on the boards; bulk moves with Q28 | Accepted |
| [27](adr-27-moving-issues.md) | Moving an issue to another project (Jira «Move») | `POST /api/issues/{key}/move` with the target project, type and status; `odt.issue.move` in the source and `odt.issue.create` in the target; a new key, the old ones kept in `moved_key` and resolved by every lookup; values that do not fit listed and confirmed, never dropped silently; one event `IssueMoved`, webhooks of both projects | Accepted |
| [28](adr-28-parent-and-subtasks.md) | Parent and subtasks (Jira hierarchy, T5) | Three fixed levels: epic, then story, task and bug, then a new type `subtask`; `parent` a field of the child (`parent_id`), set with `odt.issue.edit` on the child; `GET /api/issues/{key}/children` with progress; history, search and ODQL `parent =`; no story points on subtasks; questions A–E for the maintainer (cross-project parent, backlog, delete, done parent, move) | Proposed |
